# 浏览器体感游戏库交付计划

## 当前结论

本期游戏库采用 `MediaPipe Pose + Phaser/React Canvas + 平台正式入库链路`。

MediaPipe 负责姿态识别和关键点数据采集；Phaser/React Canvas 只负责游戏舞台、节奏反馈和训练视觉表现；训练结果仍由平台统一生成并提交到 `training_session`、`training_result`、`motion_metric`。这样可以扩展更多游戏，同时保持客户最关心的“不同条件下收集人的结构化数据”口径一致。

## 客户补充后的扩充方向

客户补充后的重点是多方案干预和数据采集，不是单个游戏的复杂度。游戏不用追求复杂度，游戏复杂度不是主交付指标；正式交付优先看方案数量和覆盖面、思维类/运动类分类、采集指标是否完整、趋势是否可复盘、医生是否能据此调整干预。

保留现有 Unity、浏览器体感和认知网页训练内容。新增游戏可以是 `cognitive_web`、`browser_pose_canvas` 或 Unity WebGL，但必须按同一正式入库、授权、运行时资源、采集批次、质量门禁和审计边界验收，不能因为某类运行时缺失而切换到另一类玩法。

运动类康复干预游戏扩充池：

- 乒乓球：上肢触达、反应速度、左右协调。
- 羽毛球：步态/重心转移、上肢挥动节奏、视动反应。
- 太极拳：低强度姿势控制、节律同步、动作稳定性。
- 节奏光剑：节拍跟随、上肢快速反应、双侧协调。
- 虚拟园艺：抓取/放置、持续注意、生活化任务训练。
- 虚拟家乡记忆：运动路径探索、空间定位、情境记忆结合。

思维类干预游戏扩充池：

- 记忆配对：短时记忆、翻牌顺序、错误类型分布。
- 快速计算：计算速度、正确率、平均反应时间。
- 麻将：规则记忆、选择判断、操作序列。
- 虚拟扑克牌：分类、排序、抑制控制、提示/跳过记录。
- 解谜游戏：问题解决、步骤规划、难度等级进展。

运动类指标应覆盖：游戏完成度、单次训练时长、平均反应时间、动作准确率、错误类型分布、肢体对称性、节奏同步度。

思维类指标应覆盖：开始/结束时间、每题正确/错误及反应时间、用户操作序列、难度、提示/跳过，并自动计算正确率、平均反应时间、错误类型分布。

康复进度指标应覆盖：各游戏得分变化曲线、反应时间下降率、完成度提升率、难度等级进展。

## 已内置的正式浏览器体感游戏

- `pose_reaction_hit`：上肢反应触达，训练反应速度、注意保持和上肢触达控制。
- `mirror_sequence`：镜像序列，训练工作记忆、动作顺序保持和双侧上肢协调。
- `nebula_sort`：星云分拣，训练选择性注意、反应抑制和视觉分类能力。
- `balance_breath`：平衡呼吸舱，训练稳定站姿、节律控制和低强度持续注意。
- `bilateral_rhythm_sync`：双侧节律同步，训练双上肢交替控制、节拍跟随和左右协调。
- `orbital_trace_follow`：轨迹追踪，训练上肢连续控制、视觉追踪和动作平滑度。
- `center_shift_bridge`：重心转移桥，训练站立重心转移、躯干控制和姿势稳定。

以上游戏均为 `browser_pose_canvas`，要求：

- `status=active`
- `buildStatus=released`
- `releaseChannel=production`
- `bridgeProtocolVersion=1.0.0`
- `supportedInputModes=["camera_pose"]`
- 必须采集 `reaction_time_ms`、`target_hit_rate`、`pose_visibility_avg`、`arm_raise_accuracy`

## 临床说明字段交付要求

每个正式浏览器体感游戏必须提供面向医生、治疗师和患者端展示的临床说明字段，字段内容应与游戏训练目标、采集指标和质量门禁保持一致。

- 适用人群：说明适合开展该训练的患者能力基础、训练阶段和主要功能诉求。
- 停止/禁忌提醒：说明需要暂停训练、终止训练或不建议开展训练的临床风险场景。
- 训练目标：说明该游戏主要训练的运动、认知或姿势控制能力。
- 指标解释：说明训练结果中核心指标的含义、观察重点和临床解读口径。
- 医生调整建议：说明医生或治疗师可调整的训练参数，以及调整对训练难度和安全性的影响。
- 用户操作说明：说明患者进入训练后的操作方式、注意事项和完成条件。

## 免费技术组件

- MediaPipe：Apache-2.0，用作浏览器姿态识别基础。
- Phaser：MIT，用作部分浏览器游戏的 2D 舞台表现。
- React Canvas/DOM：项目自研表现层，用于轻量训练。

Phaser 已作为 Web 端依赖接入，运行时只在客户端动态加载。Phaser 舞台加载失败时，训练会阻断并提示，不能退回其他玩法或生成结果。

## 异常边界

- 未配置的 `game.code` 会阻断，不会自动套用 `pose_reaction_hit`。
- 摄像头、采集批次、姿态指标、payload hash 任一缺失时不能生成正式结果。
- 采集质量不足时不能提交有效训练结果。
- 不使用固定成绩、mock、demo、seed_import 或人工伪造指标。
- 不长期保存完整视频，只保存结构化指标和必要摘要。

## 后续扩充规则

新增游戏不强制 Unity。优先按以下顺序选型：

- 轻量 2D 训练：MediaPipe + Phaser。
- 简单低成本训练：MediaPipe + React Canvas。
- 高表现 3D 或客户已有资源：Unity WebGL。
- 需要复杂 3D 且不依赖 Unity 授权生态时，可另评估 Three.js。

每新增一个正式游戏，必须同时补：

- `browser-pose-game-library.ts` 游戏配置。
- 正式游戏入库脚本或迁移内容；初始化数据不得作为生产训练数据。
- 患者端训练说明。
- required metrics 与质量门禁。
- 自动化测试覆盖和待执行的现场验收记录。
