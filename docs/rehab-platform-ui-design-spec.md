## 2. UI 目标

本项目 UI 不只是“好看”，而是要同时满足三种不同类型的体验目标：

1. 患者端：低认知负担、单任务明确、鼓励感强、失败成本低
2. 医师端：高信息密度、判断路径短、异常信息突出、编辑效率高
3. 管理员端：结构稳定、规则清晰、检索快、审计感强

因此本项目采用：

`统一品牌视觉 + 分角色信息密度 + 分角色交互复杂度`

## 3. 视觉方向

### 3.1 视觉关键词

- 温暖
- 专业
- 安全
- 鼓励性
- 非医疗恐惧感
- 非游戏化炫技

### 3.2 风格定义

采用“`Warm Clinical Calm`”视觉方向：

- 底色温和，不使用冷白医院风
- 主色偏蓝绿，传达稳定与信任
- 辅色使用杏色、米金色，提供鼓励感和情绪温度
- 卡片有轻微层次，不使用厚重拟物
- 动效克制，避免对老年用户造成干扰

### 3.3 分角色视觉语气

#### 患者端

- 更柔和
- 更大字号
- 更少干扰元素
- 更明显的主按钮
- 更强的语音/状态反馈

#### 医师端

- 更稳重
- 更高信息密度
- 更清晰的风险色和状态标签
- 更强调列表、筛选、对比和时间线

#### 管理员端

- 更中性
- 更偏治理后台
- 更强调结构和检索
- 弱化情绪化表达

## 4.2 字体系统

### 4.2.1 推荐字体

- 中文主字体：`HarmonyOS Sans SC`
- 中文兼容字体：`Source Han Sans SC` / `Noto Sans SC`
- 数字与英文辅助字体：`IBM Plex Sans`

### 4.2.2 使用原则

- 患者端正文不低于 `18px`
- 医师端正文不低于 `15px`
- 后台表格正文不低于 `14px`
- 行高默认 `1.5` 到 `1.65`
- 数值、时间、评分优先使用等宽数字风格

### 4.2.3 字号层级

| Token | 字号 | 用途 |
|---|---|---|
| `display-lg` | `40px` | 欢迎页主标题 |

| `headline-md` | `26px` | 页面一级标题 |
| `title-lg` | `22px` | 卡片大标题 |
| `title-md` | `18px` | 卡片标题、模块标题 |
| `body-lg` | `18px` | 患者端正文 |
| `body-md` | `16px` | 常规正文 |
| `body-sm` | `14px` | 后台辅助文本 |
| `label-md` | `13px` | 标签、状态、说明 |

| Token | 值 | 用途 |
|---|---|---|
| `shadow-1` | `0 6px 20px rgba(23,57,69,0.06)` | 普通卡片 |

规则：

- 患者端允许更明显但柔和的阴影
- 医师端与管理员端阴影更克制，优先靠边界和块级分区建立层次

## 4.6 按钮规范

### 主按钮

- 高度：`52px` 患者端，`44px` 医师/管理员端
- 圆角：`16px`
- 默认背景：`brand-500`
- 悬停：`brand-700`
- 禁用：`line-300 + ink-500`

### 次按钮

- 白底 + `brand-500` 边框
- 用于返回、稍后处理、查看详情

### 危险按钮

- 使用 `error-600`
- 必须配合确认弹窗

## 4.7 表单规范

### 患者端

- 一屏只做一类输入
- 单字段大卡片式布局优先
- 错误提示紧贴字段下方
- 支持语音辅助或更大点击热区

### 医师/管理员端

- 标签在上
- 支持 2 列表单，但单行不超过 2 个复杂输入
- 风险等级、计划状态、授权状态必须有语义色标签

## 4.8 卡片规范

### 患者端卡片

- 大留白
- 大标题
- 强主按钮
- 文案短句
- 一卡一任务

### 医师端卡片

- 信息块组合
- 支持多维信息并列
- 适合嵌入标签、状态、时间、操作按钮

### 管理员端卡片

- 更偏概览面板
- 数值 + 状态 + 快捷操作

## 4.9 状态规范

### 风险等级

- `低风险`：蓝绿标签
- `中风险`：杏色标签
- `高风险`：红棕标签

### 训练状态

- `未开始`：灰蓝
- `进行中`：品牌蓝绿
- `已完成`：成功绿
- `已中断`：暖橙
- `同步失败`：错误红

### 计划状态

- `待确认`
- `生效中`
- `已暂停`
- `已结束`

状态必须同时通过：

- 颜色
- 文本
- 图标

共同表达，不能只靠颜色区分。

## 4.10 图表规范

优先图表类型：

- 训练趋势：折线图
- 完成率：柱状图
- 风险分布：堆叠条或环图
- 单次训练评分：卡片指标 + 微型趋势线

规则：

- 图表颜色不超过 4 个主色
- 风险色只用于风险类图表
- 医师端图表优先显示可解释信息，不做炫技式 3D 图

## 4.11 动效规范

### 时长

- 微交互：`180ms`
- 页面切换：`240ms`
- 模态浮层：`280ms`
- 成果反馈动画：不超过 `400ms`

### 原则

- 患者端动效要有鼓励感，但不能频繁闪烁
- 训练进行页动效应服务状态提示，不做装饰性运动
- 所有页面必须支持 `reduced motion`

## 4.12 无障碍与老年友好

### 必须满足

- 正文字体不小于 `16px`
- 患者端点击目标不小于 `48x48`
- 文本对比度不低于 `4.5:1`
- 可键盘访问
- 图标按钮必须有文字或 `aria-label`

### 老年友好规则

- 文案尽量短句
- 一屏只放一个主任务
- 不使用纯占位符替代标签
- 避免多个同级 CTA 并列
- 重要提示使用图标 + 标题 + 简短说明
- 所有失败状态必须给出下一步动作

## 5. 响应式策略

### 患者端

- 以 `375px` 宽度为主基准
- 平板宽度适配 `768px`
- 不依赖 hover

### 医师/管理员端

- 以 `1440px` 后台场景为主
- 兼容 `1280px`
- 表格与筛选区允许在 `1024px` 下重排

## 7. 医师端 P0 高保真页面规格

### 7.1 医师登录页

页面目标：

- 快速、安全进入工作台

视觉重点：

- 结构简洁
- 品牌感比患者端更克制
- 表单区居中，附带机构信息

### 7.2 患者列表页

页面目标：

- 快速检索和识别待处理患者

信息层级：

1. 搜索与筛选
2. 患者列表
3. 待处理异常摘要

关键模块：

- 顶部筛选条
- 患者表格/卡片混合列表
- 风险标签
- 快捷进入按钮

视觉重点：

- 列表高可读
- 风险与待处理状态一眼可见

### 7.3 患者详情总览页

页面目标：

- 汇总患者当前状态

关键模块：

- 基础资料卡
- 最近评估卡
- 当前计划卡
- 训练摘要卡
- 时间线模块

视觉重点：

- 采用左右分栏
- 左侧主业务信息，右侧异常与快捷操作

### 7.4 评估结果页

页面目标：

- 快速理解评估结果与历史变化

关键模块：

- 评分摘要
- 结构化量表分项
- AI 摘要解释
- 历史评估记录

视觉重点：

- 分项卡 + 风险摘要组合
- 图表克制但清晰

### 7.5 风险分级确认页

页面目标：

- 让医师确认或修正系统风险判断

关键模块：

- 当前风险等级主卡
- 判断依据摘要
- 人工修正入口
- 修正原因填写区

视觉重点：

- 风险等级视觉层级非常高
- 修正区与原值区明确分隔

### 7.6 康复计划确认/编辑页

页面目标：

- 确认、调整并下发计划

关键模块：

- 系统推荐计划摘要
- 计划编辑表单
- 项目组合列表
- 版本提示

关键状态：

- 草稿
- 待确认
- 生效中
- 已暂停

视觉重点：

- 编辑区和推荐区对照展示

### 7.7 训练记录与结果页

页面目标：

- 回看训练结果并判断趋势

关键模块：

- 记录表格
- 趋势图
- 单次详情抽屉
- 异常标记

视觉重点：

- 上方趋势，下方记录
- 异常行用轻强调而不是大面积警告红

### 7.8 异常提醒/待处理页

页面目标：

- 集中处理未完成、异常结果、长期未训练患者

关键模块：

- 待处理列表
- 异常分类筛选
- 处理动作区

视觉重点：

- 风险优先级排序
- 快速处理动作固定在列表右侧

## 9. 家属端建议

家属端在首轮不必全部高保真，但建议保留统一风格的轻量规范。

首批建议重点页面：

- 绑定患者/授权确认页
- 家属首页/患者进展概览页
