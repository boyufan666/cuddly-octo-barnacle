## 2. UI 目标

本项目 UI 不只是“好看”，而是要同时满足四种不同类型的体验目标：

1. 患者端：低认知负担、单任务明确、鼓励感强、失败成本低
2. 医师端：高信息密度、判断路径短、异常信息突出、编辑效率高
3. 管理员端：结构稳定、规则清晰、检索快、审计感强
4. 家属端：摘要清楚、提醒克制、隐私边界明确、照护协同轻量

因此本项目采用：

`统一品牌视觉 + 分角色信息密度 + 分角色交互复杂度`

## 3. 视觉方向

### 3.1 视觉关键词

- 克制
- 清晰
- 可靠
- 低干扰
- 临床可信
- 简约高级
- 业务主线优先

### 3.2 风格定义

当前执行口径统一为“`Minimal Premium Clinical Rebuild`”视觉方向：

- 底色温和，不使用冷白医院风
- 主色偏蓝绿，传达稳定与信任
- 辅色只用于状态和少量鼓励反馈，不做大面积装饰
- 卡片和面板克制，常规业务容器圆角优先控制在 `8px`，不做营销式大卡片堆叠
- 患者/家属一屏一个主要任务，医师/管理端以列表、分区和表单效率为主
- 运行时、供应商、验收证据、原始 payload、审计导出等技术治理内容只进入管理员/审计员界面或验收脚本
- 动效克制，避免对老年用户造成干扰

视觉否决线：

- 常规业务页面使用轻边框和低对比线条建立层次，不使用大卡片、明显投影、玻璃、渐变或营销英雄区。
- 患者端通过任务清晰度、字号和可点击面积提升可用性，不通过大卡片或明显阴影制造高级感。
- 任何页面如果依赖能力说明、技术展示或视觉装饰解释自身价值，应回到业务任务流重写。
- 训练结果提交失败不得计为流程成功，不得进入成功记录、医生复核完成、家属进展或交付通过证据。

### 3.3 分角色视觉语气

#### 患者端

- 更柔和
- 更大字号
- 更少干扰元素
- 更明显的主按钮
- 更强的语音/状态反馈

#### 医师端

- 更稳重
- 更高信息密度
- 更清晰的风险色和状态标签
- 更强调列表、筛选、对比和时间线

#### 管理员端

- 更中性
- 更偏治理后台
- 更强调结构和检索
- 弱化情绪化表达

#### 家属端

- 更像照护协同工具
- 强调今日关注、进展摘要和注意事项
- 避免临床判断和原始数据压力
- 明确可见范围、授权状态和隐私边界

## 4.2 字体系统

### 4.2.1 推荐字体

- 中文主字体：`HarmonyOS Sans SC`
- 中文兼容字体：`Source Han Sans SC` / `Noto Sans SC`
- 数字与英文辅助字体：`IBM Plex Sans`

### 4.2.2 使用原则

- 患者端正文不低于 `18px`
- 医师端正文不低于 `15px`
- 后台表格正文不低于 `14px`
- 行高默认 `1.5` 到 `1.65`
- 数值、时间、评分优先使用等宽数字风格

### 4.2.3 字号层级

| `body-sm` | `14px` | 后台辅助文本 |

## 4.4 圆角系统

| Token | 值 | 用途 |
|---|---|---|
| `radius-sm` | `4px` | 细小标签、紧凑输入 |
| `radius-md` | `8px` | 普通卡片、按钮、表单控件 |
| `radius-lg` | `8px` | 患者端任务容器、模块容器 |
| `radius-pill` | `999px` | 胶囊按钮、状态标签 |

规则：

- 常规业务容器、按钮、卡片、表单控件优先使用 `8px` 或更小圆角。
- 患者端通过字号、留白和主按钮层级提升可用性，不通过大圆角卡片堆叠制造装饰感。
- 确需沉浸训练画布或模态浮层时，由具体组件通过稳定尺寸和清晰边界处理，不新增全局大圆角 token。

## 4.5 阴影与层级

| Token | 值 | 用途 |
|---|---|---|
| `shadow-1` | `0 4px 14px rgba(23,57,69,0.04)` | 极轻浮层辅助 |
| `shadow-2` | `0 10px 28px rgba(23,57,69,0.08)` | 必要浮层、菜单、模态 |

规则：

- 患者端层级优先靠留白、边界、字号和单主任务结构；阴影仅作极轻辅助。
- 医师端与管理员端优先靠表格、列表、分区标题和低对比边界建立层次。
- 常规业务容器默认不使用投影。

## 4.6 按钮规范

### 主按钮

- 高度：`52px` 患者端，`44px` 医师/管理员端
- 圆角：`8px`
- 默认背景：`brand-500`
- 悬停：`brand-700`
- 禁用：`line-300 + ink-500`

### 次按钮

- 白底 + `brand-500` 边框
- 用于返回、稍后处理、查看详情

### 危险按钮

- 使用 `error-600`
- 必须配合确认弹窗

## 4.7 表单规范

### 患者端

- 一屏只做一类输入
- 单字段/单任务分区优先，使用紧凑稳定容器，不使用大卡片堆叠
- 错误提示紧贴字段下方
- 支持语音辅助或更大点击热区

### 医师/管理员端

- 标签在上
- 支持 2 列表单，但单行不超过 2 个复杂输入
- 风险等级、计划状态、授权状态必须有语义色标签

## 4.8 业务容器规范

### 患者端任务区

- 清晰留白
- 明确标题
- 单主动作
- 文案短句
- 少容器堆叠

### 医师端业务区

- 信息块组合
- 支持多维信息并列
- 适合嵌入标签、状态、时间、操作按钮

### 管理员端业务区

- 更偏概览面板
- 数值 + 状态 + 快捷操作

## 4.9 状态规范

### 风险等级

- `低风险`：蓝绿标签
- `中风险`：杏色标签
- `高风险`：红棕标签

### 训练状态

- `未开始`：灰蓝
- `进行中`：品牌蓝绿
- `已完成`：成功绿
- `已中断`：暖橙
- `同步失败`：错误红

### 计划状态

- `待确认`
- `生效中`
- `已暂停`
- `已结束`

状态必须同时通过：

- 颜色
- 文本
- 图标

共同表达，不能只靠颜色区分。

## 4.10 图表规范

优先图表类型：

- 训练趋势：折线图
- 完成率：柱状图
- 风险分布：堆叠条或环图
- 单次训练评分：卡片指标 + 微型趋势线

规则：

- 图表颜色不超过 4 个主色
- 风险色只用于风险类图表
- 医师端图表优先显示可解释信息，不做炫技式 3D 图

## 4.11 动效规范

### 时长

- 微交互：`180ms`
- 页面切换：`240ms`
- 模态浮层：`280ms`
- 成果反馈动画：不超过 `400ms`

### 原则

- 患者端动效要有鼓励感，但不能频繁闪烁
- 训练进行页动效应服务状态提示，不做装饰性运动
- 所有页面必须支持 `reduced motion`

## 4.12 无障碍与老年友好

### 必须满足

- 正文字体不小于 `16px`
- 患者端点击目标不小于 `48x48`
- 文本对比度不低于 `4.5:1`
- 可键盘访问
- 图标按钮必须有文字或 `aria-label`

### 老年友好规则

- 文案尽量短句
- 一屏只放一个主任务
- 不使用纯占位符替代标签
- 避免多个同级 CTA 并列
- 重要提示使用图标 + 标题 + 简短说明
- 所有失败状态必须给出下一步动作

## 5. 响应式策略

### 患者端

- 以 `375px` 宽度为主基准
- 平板宽度适配 `768px`
- 不依赖 hover

### 医师/管理员端

- 以 `1440px` 后台场景为主
- 兼容 `1280px`
- 表格与筛选区允许在 `1024px` 下重排

## 6. 患者端 P0 高保真工作区规格

登录后直接进入角色工作区，不做营销式欢迎页、演示页或技术交付首页。当前患者端一级路径固定为 `今日 -> 训练 -> 记录 -> 我的`：`今日` 承载本日任务与当前计划，`训练` 承载训练准备和运行时，`记录` 承载训练反馈、历史和阶段进展，`我的` 承载档案、授权和家属绑定。患者端不得出现 `engine`、`license`、`sensing`、`MediaPipe`、`Phaser`、`manifest`, `bridge`, `audit ID`, 原始 evidence、provider payload、脱敏导出或审计治理等内部术语。

### 6.1 今日工作区

页面目标：

- 成为患者登录后的默认首页。
- 展示今日训练任务、当前计划状态、阻断原因和唯一主 CTA。

信息层级：

1. 今日训练任务
2. 当前计划摘要
3. 等待/阻断/完成状态
4. 开始训练准备或查看记录的主按钮

关键模块：

- 今日训练主任务区
- 当前计划摘要
- 阻断原因提示
- 今日训练入口

关键状态：

- 有任务未完成
- 已完成今日任务
- 等待医生下发训练安排
- 缺少授权或设备检查

交互要点：

- 登录后直接进入今日工作区。
- 今日最重要任务始终置顶。
- 页面只保留一个主动作；无计划时说明等待医生安排，不展示空白或技术排查入口。

视觉重点：

- 任务区清晰但克制。
- 主按钮显眼，辅助信息收敛为短句。

### 6.2 训练工作区

页面目标：

- 完成训练准备、训练运行和训练完成确认。
- 保留正式 runtime 能力，但患者只看到业务语言。

信息层级：

1. 训练安排
2. 摄像头/麦克风授权和站位检查
3. 训练运行区域
4. 完成本次训练按钮

关键模块：

- 准备检查清单
- 摄像头/站位提示
- 正式训练运行区
- 单主操作区

关键状态：

- 准备未完成
- 可开始训练
- 训练进行中
- 训练中断或设备不可用
- 结果同步失败

交互要点：

- 若训练需要摄像头，授权和站位检查在工作区内就地处理。
- 训练运行时只展示动作提示、剩余状态和完成动作。
- 不展示采集协议、质量证据、运行时清单、供应商或审计信息。

视觉重点：

- 训练运行区占据主要面积。
- 顶部状态条极简，CTA 固定且不被画布挤出视口。

### 6.3 记录工作区

页面目标：

- 展示本次训练结果、近期历史、医生反馈和计划/游戏库。
- 体现“风险评估辅助、干预训练、数据采集”的方案价值，而不是强调游戏复杂度。

信息层级：

1. 最近一次训练结果
2. 近期训练历史
3. 医生反馈和复核状态
4. 计划库与 `思维训练` / `运动训练`

关键模块：

- 训练反馈摘要
- 历史训练列表
- 近期趋势
- 计划库和训练分类

关键状态：

- 有历史记录
- 空记录
- 结果等待医生复核
- 今日训练已完成

交互要点：

- 默认展示最近 7 天。
- 未知标签不透出为患者可见目的。
- 医生复核状态用患者安全语言表达。

视觉重点：

- 趋势轻量，列表紧凑。
- 分类和目的标签简洁，不出现 runtime 技术名。

### 6.4 我的工作区

页面目标：

- 汇总个人档案、隐私同意、设备授权、家属绑定和可见范围。
- 让患者理解哪些信息被谁看见。

信息层级：

1. 档案摘要
2. 授权状态
3. 家属绑定
4. 可见范围说明

关键模块：

- 档案摘要
- 隐私同意与撤回入口
- 摄像头/麦克风授权状态
- 家属绑定和可见范围

关键状态：

- 未授权
- 已授权
- 授权撤回
- 家属绑定待确认

交互要点：

- 授权状态必须清楚说明影响。
- 家属端可见范围用短句说明，不展示内部 ID、审计编号或原始证据。

视觉重点：

- 信息分区清楚，少卡片堆叠。
- 敏感状态使用文本和图标共同表达。

## 7. 医师端 P0 高保真页面规格

### 7.1 医师登录页

页面目标：

- 快速、安全进入工作台

视觉重点：

## 8. 管理员端 P0 高保真页面规格

当前管理员端一级路径固定为 `账号 -> 内容 -> 配置 -> 审计`。供应商 readiness 收纳在 `配置`，脱敏导出收纳在 `审计`。运营统计只能作为治理页内摘要，不作为最终角色流入口。管理员端可以展示 AI/STT/TTS、Unity WebGL、browser pose、证据链和导出审批状态；不得把这些治理字段下沉到患者端或家属端。

### 8.1 账号治理页

- 处理账号开通、冻结、角色绑定和权限范围

### 8.2 内容治理页

### 8.3 配置治理页

## 9. 家属端交付规格

当前家属端一级路径固定为 `照护 -> 进展 -> 提醒 -> 我的`。本期交付为患者授权范围内的私有照护圈，不是公开社交广场；公开社交必须在客户确认可见范围、审核机制、隐私协议和运营责任后另行验收。

首批建议重点页面：

- 绑定患者/授权确认页
- 照护页
- 进展页
- 提醒页
- 我的页

视觉语气：

- 更像陪护协同界面
- 弱化专业压力
- 强调“今天需要关注什么”
- 只展示脱敏进展，不展示原始评估转写、原始动作指标、审计 ID 或导出入口
- 注意事项以医生确认内容和异常关注提示为主，家属端不承担临床判断
