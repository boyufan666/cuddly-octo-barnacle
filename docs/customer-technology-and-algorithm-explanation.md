# 项目技术与算法说明（客户沟通版）

## 1. 整体技术架构

本项目建议采用 `Web 平台 + AI 服务 + Unity/体感训练模块 + 数据后台` 的架构。

- 前端：`Next.js / React / TypeScript / Ant Design`
- 后端：`NestJS / Prisma / PostgreSQL / Redis`
- AI 服务：`Python / FastAPI`
- 体感训练：`Unity WebGL` 或浏览器训练壳
- 数据存储：`PostgreSQL + 对象存储`
- 部署：可采用 `Docker / Nginx / HTTPS / 云服务器或私有化部署`

整体会围绕一个康复闭环建设：

`AI 评估 -> 风险分级 -> 个性化方案匹配 -> 体感游戏训练 -> 数据回传 -> 医师确认/调整 -> 家属协同 -> 后台审计`

## 2. 是否会用协同过滤算法

协同过滤可以作为后续智能推荐增强，但不建议作为一期核心算法。

原因是康复训练属于健康辅助场景，早期数据量不足，而且推荐结果必须可解释、可由医生确认。相比“猜你喜欢”，一期更适合采用可解释的推荐方式：

- 风险分级规则
- 患者认知能力画像
- 游戏标签匹配
- 训练表现评分
- 医师人工确认与调整

等平台积累足够数据后，可以逐步引入：

- 协同过滤
- 相似患者匹配
- 效果预测模型
- 多臂老虎机策略
- 强化学习式难度优化

对客户可以这样表达：一期先做“可解释、可审核、医生可调整”的推荐算法；二期在数据积累后引入协同过滤和相似患者推荐，提升个性化匹配效果。

## 3. AI 评估能力

AI 评估由三部分组成：

- 语音识别：将患者语音回答转成文字。
- 量表评估：支持 MMSE、CDR 等结构化评估流程。
- 大模型结构化分析：根据问答内容、量表分数、反应时间等信息生成评估摘要。

输出结果包括：

- 认知风险等级，例如轻度、中度、重度风险
- MMSE/CDR 等评估分数
- 记忆力、定向力、执行力、语言表达等能力画像
- AI 分析摘要
- 推荐训练方向

需要强调：AI 做辅助评估与辅助建议，最终风险等级和康复计划由医生确认或调整。

## 4. 个性化康复方案匹配

个性化方案不是普通推荐，而是基于康复目标做训练匹配。

系统会结合以下信息：

- AI 评估结果
- 认知风险等级
- 记忆、注意、执行力等分项能力
- 动作能力与运动强度
- 历史训练表现
- 医师配置规则
- 游戏库标签与适用人群

然后自动推荐 1-3 个训练游戏，并生成：

- 每日训练时长
- 每周训练频次
- 游戏组合
- 难度阶梯
- 推荐依据

医生可以在后台调整推荐结果，系统会保留 AI 原始推荐、医生调整结果和调整原因。

## 5. 体感小游戏与实时数据采集

体感训练可通过 `Unity WebGL` 或浏览器训练壳运行。训练中通过摄像头进行动作识别，采集结构化训练指标。

可采集的数据包括：

- 训练开始与结束时间
- 游戏完成度
- 游戏得分
- 动作准确率
- 反应时间
- 有效动作次数
- 运动强度
- 难度变化记录
- 训练中断原因

动作识别可接入人体关键点识别、动作轨迹分析、姿态判断等能力。原则上不长期保存完整视频，只保存训练指标和必要结果摘要，降低隐私风险。

## 6. 实时难度调整

游戏难度会根据患者前期评估和实时训练表现动态调整。

示例规则：

- 准确率高、反应稳定：逐步提升游戏速度或复杂度。
- 连续失误、反应变慢：降低速度，减少干扰。
- 动作识别异常：提示重新校准或暂停训练。
- 表现良好：给出语音或视觉鼓励。

一期可先实现规则版动态调节，后续再升级为数据驱动的智能自适应模型。

## 7. 家属协同能力

家属端复用统一账号体系，通过 `家属账号 + 患者授权绑定` 进入。

家属可查看：

- 今日训练任务
- 训练完成情况
- 阶段进展摘要
- 提醒消息
- 基础康复建议

家属不可查看：

- 完整病历
- 原始 AI 对话内容
- 未脱敏敏感信息
- 医师内部备注
- 康复方案修改入口

这样既能支持家庭照护，又能控制隐私边界。

## 8. 安全与隐私保护

平台会采用 `RBAC 角色权限 + 数据范围控制 + 授权同意 + 审计日志` 的安全方案。

核心措施包括：

- 患者、医师、家属、管理员分级权限
- 家属必须授权绑定后才能查看摘要数据
- 管理员默认查看脱敏运营数据
- 姓名、手机号、健康指标等敏感数据加密或受控存储
- HTTPS 加密传输
- 密码不可逆哈希
- 导出数据自动脱敏
- AI 分析、训练回传、数据查看、修改、导出全部记录审计日志

## 9. 数据采集与过滤技术方案

这里的“过滤”建议拆成两层讲：

- 数据过滤：把采集到的数据做清洗、校验、去噪、脱敏和质量判断。
- 推荐过滤：在游戏库里筛选适合患者的训练项目，后期可加入协同过滤。

### 9.1 数据采集怎么做

一期建议采用 `结构化事件采集 + 训练结果入库 + 关键动作指标留存` 的方案，不建议长期保存完整视频。

采集链路：

`患者端/Unity 游戏 -> 前端采集 SDK -> 后端采集接口 -> 队列/缓存 -> PostgreSQL 入库 -> 统计分析/推荐算法`

推荐技术：

- 前端采集：`TypeScript SDK`，统一封装埋点、训练事件、异常事件。
- 游戏数据回传：`Unity WebGL SendMessage / JavaScript Bridge / HTTP API`。
- 后端接收：`NestJS API`，接收训练过程、训练结果、设备状态和异常事件。
- 缓冲与补偿：`Redis + BullMQ`，用于失败重试、离线补偿、异步入库。
- 主数据存储：`PostgreSQL`，存患者、评估、计划、训练记录、动作指标、审计日志。
- 半结构化指标：`PostgreSQL JSONB`，存每次训练的动作指标摘要、AI 输出摘要、设备摘要。
- 文件存储：`MinIO/S3`，如需保存报告、关键帧、导出文件，可走对象存储。

如果后期数据量很大，再升级：

- 实时数据流：`Kafka / Pulsar`
- 分析型数据库：`ClickHouse`
- 离线数仓：`Data Lake / BigQuery / Hive`
- 特征库：`Feast` 或自建特征表

一期暂时不需要直接上 Kafka、ClickHouse 这类重型方案，除非客户明确有大量并发训练和实时大屏分析要求。

### 9.2 采集哪些数据

建议采集四类数据：

1. 用户与授权数据：用户信息、角色、家属绑定、隐私协议版本、同意时间、撤回时间。
2. AI 评估数据：量表答案、语音转文字结果、评估耗时、MMSE/CDR 分数、AI 结构化分析结果。
3. 训练与游戏数据：训练开始/结束时间、游戏 ID、计划 ID、完成度、得分、反应时间、动作准确率、运动强度、难度变化、训练中断原因。
4. 审计与系统数据：登录、查看、修改、导出、授权变更、AI 分析、训练回传、异常错误。

体感数据建议只保存“指标级数据”，例如：

- 动作准确率
- 反应时间
- 有效动作次数
- 关键点轨迹摘要
- 运动强度
- 识别置信度
- 难度调节记录

默认不长期保存完整视频流，这样更符合隐私保护要求。

### 9.3 数据过滤怎么做

数据过滤不是协同过滤，而是数据质量控制。它保证后续统计和算法不会被脏数据影响。

一期建议做这些过滤规则：

- 合法性校验：字段是否完整，患者 ID、计划 ID、游戏 ID 是否存在。
- 权限校验：当前用户是否有权限上传或查看该患者数据。
- 同意校验：是否已签署 AI 数据处理、摄像头采集、家属共享授权。
- 去重处理：同一训练结果重复提交时只保留一个有效版本。
- 异常值过滤：反应时间为 0、训练时长过短、准确率超范围等标记为异常。
- 低质量数据标记：摄像头识别置信度低、人体离开画面、设备中断等不直接用于推荐。
- 脱敏处理：导出或后台运营统计时隐藏姓名、手机号等身份信息。
- 审计留痕：所有数据查看、修改、导出、人工修正都记录日志。

过滤后的数据分为三类：

- 有效数据：进入训练记录、统计分析和推荐算法。
- 可疑数据：展示给医生参考，但不直接用于自动推荐。
- 无效数据：保留异常日志，不计入训练效果统计。

### 9.4 推荐过滤怎么做

推荐过滤是“从游戏库里筛合适的训练项目”。

一期推荐采用：

- 规则过滤：根据风险等级、禁忌事项、动作能力，先排除不适合的游戏。
- 标签匹配：根据游戏标签匹配记忆、注意力、执行力、反应等训练目标。
- 加权评分：综合评估分数、历史表现、完成率、难度适配度，给游戏打分排序。
- 医师确认：系统推荐后，医生可调整训练游戏、时长、频次和难度阶梯。

示例：

`评估结果中近记忆较弱 -> 优先推荐记忆果篮`

`反应速度下降但上肢动作能力正常 -> 推荐节奏光剑低速模式`

`连续两次训练中断 -> 下调训练强度或减少单次时长`

### 9.5 协同过滤放在哪里

协同过滤适合放在二期或三期，不建议作为一期核心。

它需要大量用户、训练记录和效果反馈，例如：

- 哪类患者使用哪些游戏后改善更明显
- 相似患者通常完成哪些训练组合
- 某个风险等级下哪种频次依从性更高

数据积累后可以做：

- 基于用户相似度的协同过滤
- 基于项目相似度的协同过滤
- 相似患者训练方案推荐
- 游戏效果预测模型
- 训练依从性预测模型

对客户可以这样说：我们会先把数据采集和数据质量体系搭好，让平台形成高质量数据沉淀；协同过滤不是第一步，而是数据积累后的智能推荐升级方向。

## 10. 一句话总结

本项目不是单纯做页面，而是用 `AI 评估 + 个性化康复推荐 + Unity 体感训练 + 数据回传 + 医生确认 + 家属协同 + 安全审计` 做完整康复闭环。协同过滤可以作为后期智能推荐增强，一期优先采用可解释、可审核、医生可调整的推荐算法。
