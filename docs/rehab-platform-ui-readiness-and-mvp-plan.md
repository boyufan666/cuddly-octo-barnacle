## 2. 总体判断

第一阶段只做：

- 患者端 `P0`
- 医师端 `P0`
- 管理员端最小 `P0`

先把以下闭环跑通：

`建档/同意 -> 评估 -> 风险 -> 计划 -> 训练 -> 结果 -> 医师调整`

家属端、体验增强、多游戏矩阵、复杂运营统计都放在后续阶段。

## 3. 阶段顺序

### 阶段 0：范围冻结与业务对齐

目标：

- 确认 `P0/P1/P2` 边界
- 确认首发角色
- 冻结首发训练闭环和首发训练项目数量

产出：

- 冻结版 PRD
- 首发角色清单
- 首发页面包

### 阶段 1：领域建模与规则定稿

目标：

- 定核心对象
- 定唯一约束
- 定状态流
- 定权限与授权规则

产出：

- 数据模型草图
- 关键业务规则
- 状态枚举
- 敏感字段分级

### 阶段 2：患者端 P0 闭环

目标：

- 做建档、同意、评估、计划、训练、结果、记录的患者侧完整链路

### 阶段 3：医师端 P0 闭环

目标：

- 做患者列表、评估查看、风险确认、计划编辑、结果回看、异常处理

### 阶段 4：管理员端最小 P0

目标：

- 账号管理
- 角色绑定
- 内容启停
- 系统配置
- 审计查询

### 阶段 5：联调、试点与补偿机制

重点验证：

- 评估失败
- 设备拒权
- 训练中断
- 结果上传失败
- 越权访问
- 授权撤回

### 阶段 6：P1 增强

再进入：

- 家属端最小协同
- 患者体验增强
- 医师模板与趋势页
- 管理员设备管理

## 4. 进入 UI 设计前必须完成的清单

下面这份清单建议在高保真设计前全部确认。低保真可以与其并行，但不能跳过。

### 4.1 范围与角色

- [ ] `范围冻结`
说明：确认首发只覆盖 `P0` 页面，不把 `P1/P2` 混入首版设计稿。

- [ ] `角色边界冻结`
说明：明确患者、医师、管理员三类首发角色的入口、目标、可见数据和禁止操作。

- [ ] `页面目录冻结`
说明：按页面清单确定首发页面包，不再反复增删主页面。

### 4.2 流程与状态

- [ ] `主流程冻结`
说明：至少把患者主流程、医师主流程、管理员主流程和对应异常流程走通一遍。

- [ ] `状态枚举冻结`
说明：统一评估状态、风险等级、计划状态、训练状态、账号状态、授权状态。

- [ ] `关键业务规则冻结`
说明：明确未评估不可正式训练、同一时间仅一个当前生效计划、训练中断不得算完成、医师人工修正必须留痕、高风险变更需确认。

### 4.3 字段与权限

- [ ] `字段字典冻结`
说明：确定患者档案、评估结果、风险结果、计划摘要、训练记录、训练结果页的展示字段和编辑字段。

- [ ] `权限矩阵冻结`
说明：明确哪些页面可看、可编辑、可操作，尤其是家属默认不可看完整病史、管理员默认不可看敏感详情。

- [ ] `同意与授权机制冻结`
说明：隐私同意、摄像头同意、AI 数据处理同意、家属共享授权这四类必须先定义清楚。

- [ ] `信息分级冻结`
说明：哪些字段脱敏、哪些字段仅医生可见、哪些字段可给家属摘要展示。

### 4.4 异常与设备

- [ ] `异常与空状态冻结`
说明：无计划、无权限、未授权、设备异常、训练中断、上传失败、评估失败、无数据页都要先定义文案与跳转。

- [ ] `内容模型冻结`
说明：至少确认首发训练项目的名称、目标、时长、难度、开始/结束条件、是否依赖摄像头。

- [ ] `结果口径冻结`
说明：完成率、得分、动作准确率、反应时间、异常标记这些指标的计算与展示口径先统一。

- [ ] `终端与设备约束冻结`
说明：首发浏览器范围、摄像头要求、网络最低要求、是否支持平板/大屏，需要先写清。

### 4.5 技术与交付

- [ ] `接口视图模型冻结`
说明：哪些页面需要聚合接口，而不是直接拼表，需要在 UI 前确认。

- [ ] `设计交付物模板冻结`
说明：页面目标、入口、核心模块、权限边界、跳转关系、字段来源这 6 项作为每张页面稿的固定说明区。

## 5. 一句话准入标准

如果要压缩成一句话，进入 UI 设计前至少要先定四件事：

- `页面边界`
- `状态与规则`
- `字段与权限`
- `异常与设备约束`

## 6. MVP 研发迭代建议

建议不要按“角色端”硬切，而按“业务闭环增量”迭代。

### 迭代 1：骨架期

完成：

- 登录 / RBAC
- 患者主档
- 医师主档
- 同意记录
- 内容主数据
- 审计骨架
- 首发页面路由骨架

产出目标：

- 系统可登录
- 可建档
- 可做基础权限区分

### 迭代 2：评估与分级

完成：

- 评估记录
- AI 结果摘要
- 风险记录
- 医师确认/修正流程

产出目标：

- 患者可完成一次评估
- 医师可看到结果并确认风险

### 迭代 3：计划生成与下发

完成：

- 康复计划
- 计划项
- 版本机制
- 计划确认/编辑
- 患者侧计划摘要

产出目标：

- 同一患者只有一个当前生效计划
- 患者能看到可执行任务

### 迭代 4：训练执行与结果回传

完成：

- 训练会话
- 训练结果
- 动作指标摘要
- 训练反馈页
- 训练记录页
- 失败补偿

产出目标：

- 患者能完成一次训练
- 医生能看到结构化结果

### 迭代 5：医师回看与异常处理

完成：

- 阶段趋势
- 异常提醒
- 待处理视图
- 计划调整记录
- 复评入口

产出目标：

- 医生可基于结果调整计划
- 闭环成立

### 迭代 6：管理员最小后台与试点

完成：

- 账号管理
- 角色绑定
- 内容启停
- 系统配置
- 审计查询
- 试点优化

产出目标：

- 具备可运维、可审计、可试点上线的最小后台

### 迭代 7：P1 扩展

完成：

- 家属端最小协同
- 患者端帮助与设备调试
- 医师模板与趋势增强

产出目标：

- 提升依从性和运营可用性
- 不影响 `P0` 主闭环稳定性

## 7. 执行原则

1. 先做 `1 个可用闭环`，不要并行铺太多训练内容。
2. UI 先从低保真把页面跳转、状态、异常走通，再上高保真。
3. 数据模型、权限矩阵、状态流转图要先于高保真定稿。
4. 家属端不要挤进首发主路径，否则会拉长授权、隐私和消息链路。
5. 研发验收不要只看页面完成，要按“患者是否能完成一次完整训练闭环、医生是否能完成一次查看与调整”验收。

## 8. 建议的 UI 启动时机

### 8.1 现在可以做的 UI

现在可以开始：

- 信息架构图
- 页面地图
- 页面跳转关系
- 关键页面低保真

### 8.2 暂时不建议全面做的 UI

现在暂时不要大面积展开：

- 全量高保真
- 全角色视觉细化
- 大面积动效规范
- 非 P0 页面视觉精修
